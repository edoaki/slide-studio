# Slide Studio スライドの作業

## 進め方

1. アプリからの依頼では、`[対象]` のページ・図（step の指定があればその step）を `[指示]` どおりに変える。`[発表]`・`[対象の原文]`・`[今の表示]`・`[必須]` も確かめる。送信後に画面が移っても対象は変わらない。
2. 原稿・図を直す（下の書き方に従う）。
3. `slide-studio check <deck>` でエラーをなくす（下の「検査」）。
4. 変えたところ、検査の結果、残った問題を短く伝える。

- 必ず変える必要はない。指示の意図が分からない・必要なデータや資料が無いときは、推測で変えずに、何が分からないか・何が要るかを伝える（その件の `ok` は false）。質問・相談だけの指示には、ファイルを変えずに答える。
- `[話し合い]` の送信ではファイルを変えない（読むだけで、書けない）。答えは普通の文章で返す。

## 下書きからスライドを作る

「スライドにして」などと頼まれたら、`decks/<deck>/memo.md` の下書きから `slides.qmd` を作る。

- HTML は必ず対象の `topics/<トピック>/html/<名前>/figure.mjs`（必要なら `style.css`）に置き、`renderStep` の形式にそろえる。旧 HTML などの素材は、外部の参照を残さず依存部品も含めて正式な図形式に移植し、原稿には `{{< fig トピック/名前 >}}` で挿入する。素材へのパスを本文に書くだけで済ませない。
- 対象読者・伝えたい結論が下書きから分からなければ、作る前に質問して答えを待つ。
- 実験結果など、まだ値が出ていないもの（下書きで「要確認」・空欄・これから測るなど）があり、`[下書きの担当からの方針]` にも扱いが書かれていなければ、作る前に「値を空けて枠だけ置く」か「載せない」かを聞いて答えを待つ。値を自分で作らない（グラフの値も同じ）。枠だけのときは、表の欄・グラフの軸などの形だけを作り、値の所は空ける。
- 既にスライドがあれば、作り直すよう頼まれていない限り全体を作り直さない。依頼に `[下書きの差分]` があれば、その変わった所だけを反映し、手で直した所・下書きに無い所は残す。

- 既存図を再利用するときも、下書きの人数・配置・数値・step 間の説明と照合する。相違があれば明示し、どちらを採用するか確認する。

## 変えてよいもの

- 発表の `decks/<deck>/`（`materials/` を除く）と、トピックの `topics/<トピック>/`（図・画像・`reference.bib`）。
- 参考資料 `decks/<deck>/materials/` は読むだけ。数値はここから取り、どのファイルから取ったかを伝える。スライドに使う画像は `topics/<トピック>/images/` に写してから参照する。グラフを作り直すスクリプトも materials の中に置かない。
- PowerPoint の雛形（`.pptx`・`.potx`）があれば配色・フォント・構成の参考にする（zip なので、色とフォントは `ppt/theme/theme1.xml`、配置は `ppt/slideLayouts/`。展開先は materials の外の一時フォルダ）。雛形に合わせるよう頼まれたら、使っている `themes/<テーマ>.css` を直す（下の「テーマの型」。共有なので同じテーマの他の発表も変わる）。

## 原稿（slides.qmd）の書き方

- slides.qmd は全体を書き直さず、対象のページの部分だけを置き換える。書く前に読み直す（別のチャットのタブが同じ時間に別のページを直していることがある）。
- front matter に `title`・`topic`・`theme`・`lang: ja`。
- `#` は章扉、`##` は1枚のスライド。見出しには `{#id}`（英小文字・数字・ハイフン、重複なし）を付け、既存の ID は変えない。
- 順は 表紙（`## タイトル {#cover .cover}`）→ 本編 → `## 参考文献 {#references}`。補足がある場合だけ、その後に `# Appendix {#appendix}` と補足ページを置く。参考文献・Appendix を埋めるために文献や補足を作らない。
- 段階表示は `::: {data-step="1"}` … `:::`（画像は `{data-step="1"}`）。
- HTML の図は1行で `{{< fig トピック/名前 >}}`（任意で `step`・`height`・`title`）。
- 画像は `images/名前`。引用は `[@key]` で、キーは `topics/<トピック>/reference.bib` のもの。bib に足す文献には `slide-studio-status = {unverified}` を付ける。
- bib に足す文献には発表先を入れる。会議は `@inproceedings` の `booktitle`、論文誌は `@article` の `journal` に書く。arXiv などのプレプリントは採録先を調べ、採録されていれば会議・論文誌の形で書く。採録を確かめられなければ `@misc` に `eprint` と `archiveprefix = {arXiv}` を書く（スライドの下の引用には arXiv 番号が出る）。発表先は論文のページや DOI で確かめ、確かめられないときは推測で書かずに利用者に伝える。
- 色はテーマの色の名前で `[語]{.accent}`（`.main`・`.muted`・`.warn`・`.good`・`.highlight`）。
- ブロックのデザインは `::: {style="--block-design:top"}` … `:::` だけで指定する。色・太さ・角丸はテーマから自動で付くため原稿に書かない。種類は `plain`（情報を整理する枠）、`top`（結論・要点）、`left`（説明・補足）、`quote`（実際の引用）、`bracket`（定義・条件・数式）、`fold`（メモ・注意・実践のヒント）。引用でない文章に quote を使わない。全ブロックを囲まず、意味のあるまとまりだけに使う。同じ役割は同じ種類で統一する。
- 影を付ける場合は `style="--block-design:fold;--block-shadow:on"`。影は任意で、通常は付けない。種類を省略すれば枠・背景なし。個別の文字色（`[語]{.warn}` など）はデザインの標準文字色より優先される。
- 表の文字サイズ・太さ・列の幅は、表を囲む `::: {style="--table-size:24px;--table-weight:700;--table-cols:200 400 400"}` … `:::` に書く（`--table-cols` は列ごとの px で、列の数と揃える）。スライドの操作で書かれた値は、依頼がない限り消さない。
- 本文・図・注記には、聞き手が内容を理解するのに要ることだけを書く。制作の事情（下書き・参考資料のどこに基づくか、下書きに無いこと、「説明用の模式図」など）は書かない。それは最後の返事で伝える。

## step の区切り方

- HTML の図を編集するときは、要素の名前・概念説明を除き、各 step に書く本文は基本的にメインメッセージ1文を1ブロックにまとめる。

- step は、発表者が止めて説明する状態を表す。各停止点には「ここで伝えるメッセージ」または「画面・生成物が切り替わる前に見せておく結果」が必要。動きが1つ終わったことだけを理由に区切らない。
- 1つの結果を段階的に作る途中や、同じ処理の繰り返しは、次の停止点まで連続して見せる。途中に独立して説明する新しいメッセージがある場合だけ区切る。選択対象・回数・数値が変わるだけなら、繰り返しごとに step を作らない。
- 同じ処理を繰り返す部分は、初回の4倍速にする。動きの `duration` と待ち時間の `hold` を原則として4分の1にし、初回の説明や新しいメッセージを伝える部分は通常速度を保つ。
- 画面・生成物が切り替わる直前の完成状態は、切り替え前に確認する停止点として残す。そこへ至る途中の停止を減らしても、結果を見せずに次の画面へ進めない。
- 作る前に、停止点ごとのメッセージまたは結果を決め、その間の動きを割り当てる。図の途中経過は `transition(from, to)` にまとめ、`steps` と `renderStep(k)` には停止する状態だけを定義する。既存の step をまとめるときも、途中の動きや処理は必要に応じて遷移に残す。
- PDF には各ページの最後の step の状態だけが載る。途中の step で見せた要素が後の step で消える・置き換わる場合は、そのページの見出しに `pdf="<step の番号>"`（1 始まり、空白区切りで複数可。例：`## 見出し {#id pdf="3"}`）を付け、その step も PDF に載せる。要素を足していくだけの step には付けない。`renderStep(k)` だけを順に読んでも話がつながるようにし、必要なメッセージをアニメーションの途中だけに置かない。短い間を取るだけなら `transition` の `hold` を使い、手動で進める step と区別する。
- 区切りは図だけでなく、前後の本文も含むページ全体で考える。HTML ファイルの末尾というだけで、説明上の区切りとはみなさない。同じ意味の本文は同じ `data-step` にまとめる。ただし現行の `data-step` は図の開始する段を指定し、後続の段は図の全 step の後に進むため、本文を図の最終状態と同時に出す指定には使えない。その結合が必要なら再生側の制約として伝え、個別の図から親ページを操作する回避策は作らない。

## 図（figure.mjs）の書き方

図は `topics/<トピック>/html/<名前>/figure.mjs`（任意で `style.css`、共通部品は `topics/<トピック>/html/_lib/`）。`index.html` はアプリが作る。

以下の `<…>` は、作る図に合わせて置き換える。

```js
export default {
  id: '<図のID>',
  title: '<図のタイトル>',
  steps: ['<最初の段階の説明>', '<次の段階の説明>'],
  renderStep(k) {  // k は 0 始まり。同じ k なら同じ SVG を返す
    return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1000 460">…</svg>`;
  },
};
```

- `transition(from, to)` は任意で、`{markup, duration, hold}` の配列を返す。途中の演出だけをここに置き、最後は `renderStep(to)` の確定状態につなげる。PDF と直接の step 移動では `renderStep(k)` が使われる。
- `hold` と `duration` の単位はミリ秒。各フレームは「現在の表示のまま `hold` 待つ → そのフレームの `markup` へ `duration` かけて変化する」の順で実行される。`hold` は、その `markup` を表示した後の待ち時間ではない。
- 説明の文字や図を見せてから変形・移動・消去する場合は、まず説明を表示するフレームを置き、次に変化させるフレームの `hold` に読む時間を指定する。例えば `[{markup: explanation, duration: 300}, {markup: result, duration: 400, hold: 2000}]` なら、説明の表示完了後に2秒待ってから結果へ変化する。説明を出すフレームの `hold` を増やしても、その説明の表示時間は延びない。`duration` を延ばすことも、表示完了後の静止時間の代わりにはならない。
- 要素を消すときは、同じ step で消えるものをすべて同じタイミングで、0.1秒程度で消す。消える要素ごとに時間差を付けない。`transition` に、消える要素をまとめて `opacity="0"` にしたフレームを `duration: 100` で1つ置く。`opacity` は `renderStep(from)` の側で `opacity="1"` と明示し、`data-key` で前後の要素を対応させる（属性が無いと補間されず、すぐ消える）。同じ step で出る要素や動く要素があれば、このフレームの後に `renderStep(to)` のフレームを続ける（最後の確定は補間されない）。
- 新しい図は `slide-studio fig new <名前> --deck <deck>` で雛形を作り、原稿に入れる1行を受け取る。
- import はローカルの相対 import だけ。外部通信（fetch・CDN など）はしない。
- 色はテーマの変数を既定値つきで使う：`var(--theme-accent, #2167a8)`（ほかに `--theme-ink`・`--theme-muted`・`--theme-header`・`--theme-rule`・`--theme-paper`・`--theme-border`）。
- トピックの図は共有なのでそのまま直し、同じ図を使う他の発表も変わることを伝える。他のトピックの図は、自分のトピックへ依存部品ごと写してから使う（同じ名前で中身が違う部品は `名前-2.mjs` にして import を直す。既存の部品を上書きしない）。

## テーマの型

- `:root` の次の変数は消さない：`--ink`・`--accent`・`--header`・`--header-ink`・`--muted`・`--warn`・`--good`・`--mark`・`--mark-ink`・`--mark-line`・`--paper`・`--rule`・`--font-body`・`--font-head`。
- 図へ色を渡す `--theme-ink:var(--ink)` などの行も残す。

## 検査

- 終える前に `slide-studio check <deck>` を流し、エラーがなくなるまで直す。途中の絞り込みに `--page <id>`、図だけなら `slide-studio check --figure <トピック>/<名前>` も使える。
- 結果は `.slide-studio/build/<deck>/checks.json`、各ページ・各 step の画像は `shots/pXX-sY.png`、問題の箇所は `issues/pXX-sY.png`。検査だけに頼らず画像も見る。
- `transition` の説明表示や待ち時間を変えたら、直前の step から通常速度で再生し、説明の表示完了後に指定時間止まってから、消去・変形・移動が始まることを確認する。step への直接移動・PDF・確定状態の画像では途中の表示時間を検証できない。再生確認ができなければ、その点を未確認として伝える。
- アプリも終わった後に検査をやり直す。

## 最後の返事

アプリから返事の JSON の形を指定されたら、それに従う。`results` に各指示の番号（`item`）、できたか（`ok`）、何をしたか（`text`）を入れる。

- 利用者に決めてもらう確認で選択肢を挙げられるものは `questions` に入れる（1回に3つまで、選択肢は2〜4個）。チャットにボタンで出る。同じ質問を`summary`・`results` の `text`に重ねて書かない。選択肢を挙げられない質問は普通に文章で聞く。答えが来るまで、その件は推測で変えない。 `item` はどの指示への確認かの番号。
